## 从哪里开始

默认新手路线为：一笔咖啡交易 → 谁在协作 → 钱/货/服务 → 单店与多店 → 支付异常 → 设计边界。

1. 先沿图里的角色、箭头和分支阅读。
2. 想看细节时点“放大这张图”，用＋/−调整大小，或用“适合宽度”。关闭后返回原位置。
3. 看完图再读一句重点，需要时展开例子、边界或自查。
4. 点“读完这一步，继续”；上一步可回看，跳读不会自动完成整条路线。
5. 岗位不同可展开路线选择；手机的完整步骤目录可按需展开。

学习进度只在当前页面打开期间保留，刷新会重置。它不是产品开发完成度或学习认证。

## GitHub Pages 部署配置与复用方法

当前站点已按方案A发布：`master` → `/ (root)`，无需自定义工作流或构建步骤。以下步骤供复用到其他仓库时参考，不表示可在未经授权时扩大资料可见范围。

先确认这份设计资料的受众和可见范围。**仓库私有不代表 Pages 网站一定私有。** 应先检查当前 GitHub 账户、组织政策和 Pages 实际支持的访问控制。若不能满足所需私密性，不应发布该资料。

该页面不需要框架、构建命令、包管理器、服务器、数据库或环境变量。

### 方案A：独立文档仓库

1. 经授权后，在指定仓库的发布分支根目录放入本目录的 `index.html` 与 `.nojekyll`。
2. 在仓库 Settings → Pages 中选择组织允许的发布方式。如支持从分支部署，选择对应分支及根目录 `/ (root)`。
3. 等待 GitHub 显示部署完成，使用它返回的真实网址。不要按仓库名猜测网址并宣称已上线。
4. 在实际网址检查主页、目录跳转、移动宽度、搜索、分类筛选、来源链接和打印预览。

### 方案B：现有仓库的文档子目录

1. 先阅读该仓库的贡献规范和现有 Pages 配置。不要覆盖已有文档或站点入口。
2. 如果已有站点，将本目录放到获准的子目录中，例如 `guide/`；最终发布根目录中的子路径也应保持一致。
3. 如果拟用 `docs/` 作为 Pages 根目录，应先确认没有冲突，再由授权负责人选择分支及目录。
4. 若仓库使用 GitHub Actions 部署，应纳入现有已授权流程。本包没有添加工作流，不自动启用权限或改变访问范围。

### 子路径兼容性

`index.html` 内所有样式、脚本和SVG均内嵌。目录和来源编号均使用页内 `#fragment`，没有 `/assets/...` 之类网站根路径依赖。因此适用于根站点、`/<仓库名>/` 或更深的文档目录，不需要改 base URL。外部来源链接固定到已核提交。
